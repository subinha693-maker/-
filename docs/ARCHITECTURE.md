# 통합인류행정부 — 아키텍처 (PHASE 1 기준)

## 기술 스택
- TypeScript + React 19 + Vite, 상태 관리 zustand
- 모바일 대응: 1080 논리 높이 고정 스테이지(폭 1920~2400 가변)를 화면에 맞춰 균일 확대/축소, 세로 화면에서는 회전 안내, PWA manifest(가로·전체화면)
- 전투/지도 렌더링에 PixiJS는 PHASE 7에서 필요 시 도입 (현재 미설치)

## 폴더 구조
| 경로 | 역할 |
|---|---|
| `src/core` | 타입(`types.ts`), 설정 로더, 새 게임 상태 생성, 게임 시간, zustand 게임 스토어, 화면 라우터 |
| `src/config` | 규칙·밸런스 설정값 (`game.json`, `balance.json`). 미확정 값은 `_placeholders`/`_placeholder`로 표시 |
| `src/data` | 콘텐츠 정의 JSON + `index.ts`(조회·무결성 검사) |
| `src/systems` | 정부 운영·연구·모집·원정·전투 시스템 (PHASE 4~) |
| `src/save` | 세이브/로드 (PHASE 2) |
| `src/tutorial` | 튜토리얼 진행 로직 (PHASE 3) |
| `src/ui/components` | 공통 컴포넌트 (Stage, Panel, Button, Tabs, Modal, TopBar, BaseView, CharacterArt, Icon) |
| `src/ui/screens` | 화면 14종 + 개발용 화면 목록 |
| `src/styles` | 디자인 토큰, 공통/화면 스타일 |
| `public/assets` | 가공된 에셋 (캐릭터 webp, Kenney 렌더 스프라이트, 아이콘) |

| `tests` | Playwright E2E (`phase1.e2e.cjs`) |

## 핵심 규칙
1. 저장 대상 상태는 모두 `GameState` 하나에 있으며 정의 데이터는 ID로만 참조한다.
2. 수치·규칙은 코드에 하드코딩하지 않고 `config`/`data`에 둔다.
3. 아직 구현되지 않은 버튼은 비활성화하고 `PHASE n 예정` 태그를 붙인다.
4. 사용자가 확정하지 않은 콘텐츠(시설·연구 항목, 난이도 수치, 대사 등)는 `(임시)`/`미정`으로 화면에 드러낸다.

## 확정된 설정 (사용자 결정)
- 모바일 구동 지원 / 제공 에셋 활용
- 전투: 두 개의 진입로(1열·2열), 각 최대 4명
- 게임 시간: 실시간 1초 = 게임 10분 (`config/game.json` `time.gameMinutesPerRealSecond`)
- 전투 중 저장 불가, 로드 시 전투 시작 직전으로 복귀 (`battle.saveDuringBattle: false`)
- 비서 NPC 이름: 아일라 / 캐릭터 이름: 시온 시라유코, 제임스 해럴드, 아이온, 링, 제라그, 마일리 스니커

## 세이브/로드 (PHASE 2)
- 슬롯: 수동 3개(확정) + 자동 저장 1개. 저장소 키 `uha.save.<slot>`, 백업 `.bak`, 임시 `.tmp`
- 안전 저장 순서: `.tmp` 기록 → 다시 읽어 검증 → 기존 본을 `.bak`으로 보관 → 본 슬롯 기록 → `.tmp` 삭제. 시작 시 `recoverInterrupted()`가 중단된 쓰기를 정리
- 로드 검사 순서: JSON 형식 → 저장 포맷 → 체크섬(cyrb53) → 버전(새 버전 거부 / 구버전은 `migrations.ts`로 단계별 변환, 경로 없으면 호환 불가) → 내용 검증(`validate.ts`, 알 수 없는 시설·부대원·연구, 중복 유물 등)
- 손상된 슬롯은 로드를 막고 사유를 표시하며, 정상 백업이 있으면 "백업으로 복구" 제공
- 자동 저장: `core/events.ts` 이벤트(원정 시작·종료, 전투 진입, 시설·연구 완료, 스토리, 튜토리얼 단계, 게임 시간 경과)를 `save/autosave.ts`가 받아 저장. 같은 시점의 요청은 1회로 병합, 전투 중에는 저장하지 않음. 트리거별 사용 여부는 `config/game.json` `save.autosave`
- 전투 중 저장 불가. 전투 진입 직전 자동 저장 → 로드 시 원정 지도(전투 직전)로 복귀
- 프로필(`uha.profile`): 최초 실행 여부, 마지막 슬롯, 사운드 설정. 세이브 슬롯과 별도 보관
- 저장소는 `StorageAdapter` 인터페이스 뒤에 있어 앱 포장 시 파일 저장 방식으로 교체 가능

## 튜토리얼 (PHASE 3)
- 대본: `src/data/tutorial.json` (10단계, 줄 단위). 줄마다 `target`(강조할 `data-tut` 앵커), `await`(클릭/신호 대기), `pose`(전신 일러스트)를 지정
- 진행: `src/tutorial/controller.ts` — 시작/다음 줄/단계 완료/건너뛰기/이어하기. 단계 완료마다 `tutorial:step` 이벤트 → 자동 저장
- 화면: `src/tutorial/TutorialHost.tsx` — 강조 영역만 뚫린 차단막(설명 중에는 강조 영역도 클릭 불가, 행동 유도 시에만 열림), 타자기 효과, 단계·대화 진행 표시, 건너뛰기 확인
- 최초 실행: 프로필 `firstRun` + 저장 데이터 없음 → 새 게임 시 안내/건너뛰기 선택. 설정에서 "튜토리얼 다시 보기"
- 이어하기: 저장된 `tutorial.step`의 `startScreen`부터 재개. 원정·전투 안내(8·9단계)는 원정 상태를 만들지 않는 훈련 모드 지도/전투 화면 사용
- 비서 NPC 아일라: 성격 확정(활발, 분위기 메이커, 친화력), 대사는 초안(`_draftDialogue: true`)

## 정부 운영 (PHASE 4)
- 시간: `core/loop.ts` — 실시간 1초 = 게임 10분 × 배속(x1/x2/x4), 일시정지. 튜토리얼·전투 중·타이틀에서는 정지. 백그라운드 복귀 시 최대 5초분만 따라잡음
- 경제: `systems/economy.ts`(순수 함수) — 시설 가동률 = 인력 충원율 × 정비 상태 계수 × 투입 자원 충족률. 생산·소비·전력은 게임 1시간 기준. 인구는 식량을 소비. 자원은 0 아래로 내려가지 않음
- 행동: `systems/government.ts` — 인력 배치(인력 유형별 한도), 운영 중지/재개, 정비, 업그레이드, 건설(빈 칸 자동 배치), 연구 시작(비용 선지불). 실패 시 사유 반환
- 공사·연구는 게임 시간으로 진행되고 완료 시 `facility:complete`/`research:complete` 이벤트 → 알림 + 자동 저장
- 경고: `systems/alerts.ts` — 자원 고갈 예상, 자원 부족 가동 저하, 인력 미배치, 정비 필요, 연구 정지
- 모든 수치(시설 목록, 인력, 생산·소비량, 전력, 비용, 공사 시간, 정비 비용, 인구 식량 소비, 연구 비용·시간)는 임시값: `data/facilities.json`, `data/research.json`, `config/balance.json`
- 세이브 호환: 시설에 `job`(공사 정보) 선택 필드 추가. 이전 세이브도 그대로 불러올 수 있음(버전 변경 없음)

## 개척부대 (PHASE 5)
- 캐릭터 확정 정보(`data/characters.json`): 이름(국/영), 무기, 전문 분야, 출신, 능력치 경향성(등급 문자), 고유 스킬명·설명. 미정: 등급, 수치 능력치, 기본 공격, 특성 내용, 스토리
- 초기 6명은 배포 요원(새 게임 시 지급). ID: shion_shirayuko, james_harold, aion, ring, jerag, miley_sneaker
- 육성(`systems/growth.ts`, `config/growth.json`): 숙련도 레벨(상한 = 등급 상한 + 작전 경력서/실무 훈장 확장), 스킬 레벨(인사 공적), 특성 슬롯(고유=인사 공적, 패시브=Phase 2, 궁극 전술=Phase 3), 전문가 등급 승급 Phase 1→2(레벨 + 국가 공인 직무 인증서)→3(레벨 + 고난도 원정 완료 + 특수 부토스 생체시료·유물 잔재), 등급별 장비 슬롯. 숫자는 모두 임시
- 레벨을 얻는 방법은 미정 → "기본 훈련(임시)"로 대체
- 재화(`data/items.json`): 인사 공적(요원별), 국가 공인 직무 인증서(행정·무장·방호 연구 완료 시 지급, 임시 매핑), 특수 부토스 생체시료·유물 잔재·작전 경력서·실무 훈장(원정 보상, PHASE 6/8에서 지급)
- 이력서 확인(`systems/recruit.ts`, `config/recruit.json`): 지원서 검토 → 신규면 편입, 보유 요원이면 그 요원의 인사 공적으로 전환. 모집 대상·확률·비용·천장은 미정(시험용 설정)
- 세이브 버전 2: 캐릭터 ID 변경(ling→ring, zerag→jerag), 요원 육성 필드, 재화, 모집 기록 추가. v1 세이브는 자동 변환

## 원정 (PHASE 6)
- `systems/expedition.ts`: 시드 기반 지도 생성(열 수는 난이도별, 첫 열=전투, 마지막 열=보스, 모든 노드 도달 가능 보장), 분기 이동(연결된 노드만), 노드 사건
- 노드 사건은 진입할 때 한 번 굴려서 `expedition.pending`에 저장 → 저장/로드로 다시 굴리거나 보상을 두 번 받을 수 없음. 사건 창 안에서도 저장 가능
- 노드: 전투·강적·보스(전투 화면 → PHASE 7 전까지 "임시 승리 처리"), 유물 획득(3택 1), 후발대 모집(보유 요원 후보, 이미 원정 중인 요원을 고르면 보급품 도착), 자원 탐색, 사건 및 선택지, 회복 및 정비, 상점 및 교환(원정 획득물로 유물 교환), 정보 및 연구 자료
- 전투 후퇴 = 원정 실패. 보스까지 완료 → 원정 완료 → 해당 난이도 완수 기록 + 다음 난이도 해금. 유물은 원정 종료 시 소멸
- 원정 획득물은 원정 중 기록만 하고 정부 반영(정산)은 PHASE 8. 심층 원정은 PHASE 9
- 임시 데이터: 유물 8종(`data/relics.json`), 사건 3종(`data/events.json`), 생성 가중치·보상량·회복량·상점 가격(`data/expedition.json` generation), 보급품 도착 효과
- 육성 변경: 작전 경력서/실무 훈장 = 서로 다른 양의 레벨 경험치(레벨 상한 확장 아님), 숙련도는 전투 숙련도 하나. 세이브 버전 3(v2→v3 자동 변환)

## 실시간 전투 (PHASE 7)
- `systems/battle.ts`(순수 시뮬레이션, 0.05초 고정 틱) + `ui/screens/BattleScreen.tsx`(렌더링·입력)
- 흐름: 전투 진입(달려오는 연출) → 웨이브 → 웨이브 사이 이동 연출 → 반복 → 승리/패배
- 2개 진입로 × 4자리(최대 8명). 적은 오른쪽에서 진입해 각 열의 가장 앞 요원 앞에서 멈춰 공격, 막는 요원이 없으면 임시 거점을 공격. 거점 HP 0 = 패배 = 원정 실패
- 자동 공격(근접/원거리 사거리), 스킬 게이지가 차면 플레이어가 발동, 교체(요원 선택 → 자리 선택; 대기열 요원 투입 시 기존 요원은 대기열로), 대기열 HP 회복, HP 0 요원은 전투 불능
- 요원 수치: 확정된 능력치 경향성(S+/S/A/B)을 등급 배율로 변환(`config/battle.json` tendencyEffects/gradeMul), 레벨·승급 단계·유물·보급품 버프 반영
- 스킬: 6명 스킬 설명대로 효과 종류 구현(둔화·명중 저하·출혈·회피 강화·기절·공격력 저하 등), 수치는 임시. 스킬 레벨에 비례해 위력 증가
- 적: 사용자 제공 스프라이트 8종(`data/enemies.json`), 이름·역할·수치는 임시. 웨이브는 노드 유형(일반/강적/보스)·난이도·시드로 생성
- 전투 결과 HP와 거점 HP는 원정에 다시 기록. 전투 중 저장 불가(진입 직전 자동 저장)
- 스프라이트 도구: `tools/sprites/slice_units.py`(캐릭터 시트 → 동작별 프레임 아틀라스), `tools/sprites/slice_enemies.py`(9×6 측면 전투 시트 → 걷기·대기·공격·피격·쓰러짐)
- 테스트용 훅: URL에 `?e2e`가 있을 때만 `window.__uhaBattle` 노출

## 전투 흐름 변경 (사용자 확정)
- A 전진(달리기, 배경 스크롤) → B 적 출현(아군 위치 유지) → C 자동 전투(원거리는 사거리 내, 근접은 바로 앞의 적만) → D 웨이브 종료(웨이브 적 전원 처치 시에만) → E 다음 웨이브 전진 → F 노드 완료 + 보상 선택 → 탐사 지도
- 배경: 사용자 제공 침수 도시 이미지(좌우 반전으로 이음매 없이 반복) + 기둥·잔해 실루엣 레이어 2종(`tools/sprites/make_battle_layers.py`). 스크롤 거리는 전투 상태(`scroll`)이며 전진 단계에서만 증가
- 전투 보상 선택은 원정 `pending`(battleReward)으로 저장되어 다시 굴리거나 두 번 받을 수 없음
- 장비 시스템은 만들지 않음(사용자 결정)

## 지역 탈환 PHASE 1: 지역 데이터·상태 (`systems/regions.ts`)
- 유한한 지역 목록(`data/regions.json`, 현재 임시 5개)과 양방향 연결, 지역 유형 5종, 상태 5단계(미확인 → 정보 확보 → 전진 거점 확보 → 통제권 확보 → 개발 완료)
- 상태 진행 조건·해금 조건은 데이터(조건 종류: 지역 상태, 작전 완료, 연구 완료, 지역 일반 원정 완수 횟수, 재화 보유)
- 일반 원정 기록은 최대 '정보 확보'(2)까지만 올릴 수 있음(데이터와 무관하게 코드에서도 차단). 통제권(4)은 그 지역의 통제 작전이 실제로 통제권을 지급한 경우에만
- 전략 작전(`data/strategicOps.json`, 지역별 전진 거점 작전 + 통제 작전): 개시 조건·선행 작전, 주요/부가 목표, 귀환 필요. 정산은 목표 달성 + 귀환일 때만, 보상·통제권은 1회만(`OpRecord`의 목표 달성/귀환/보상 지급/통제권 지급을 각각 기록)
- 상태는 내려가지 않음. 완료한 작전은 다시 개시할 수 없음
- 세이브 버전 4(v3→v4: 지역 초기 상태 + 빈 작전 기록), 검증: 알 수 없는 지역·작전, 보상 미지급인데 통제권만 있는 기록 거부

## 지역 탈환 PHASE 3: 일반 원정 연동
- 출격 경로: 전략 지도 → 지역 → 목적(자원 회수/생체시료 수집/특수 조사/잔존 위협 제거) → 출격 준비(지역·목적 선택 유지, 메뉴의 개척 작전에서도 선택 가능) → 원정
- 원정 상태에 `kind`(general/strategic), `regionId`, `purpose`, `opId` 저장(세이브 v5, v4 원정은 공업 지구·자원 회수 일반 원정으로 변환)
- 목적별 노드 가중치(`weightMul`)·획득량 배율(`lootMul`)은 `data/regions.json` generalPurposes(임시값)
- 원정 정산(`settlementFor`/`endExpedition`, 원정 종료와 같은 한 번의 처리라 중복 불가): 결과별 회수율(완료 100%·귀환 70%·실패 30%, 임시)로 정부 자원 반영, 작전 경력서·실무 훈장 지급, 보스 클리어 시 특수 부토스 생체시료·유물 잔재 지급(임시 수량, `data/expedition.json` settlement)
- 일반 원정 종료 시 지역 기록(출격/완수) 갱신. 상태는 최대 '정보 확보'(2), 통제권·영토 변화 없음 — 51회 연속 원정 단위 테스트와 2회 실제 플레이 테스트로 확인

## 지역 탈환 PHASE 4: 전략 작전
- 지역 상세 "작전 개시"(개시 조건·선행 작전 충족 시) → 전략 작전 준비(작전 브리핑) → `launchStrategicOp`: 작전 시도 기록(`startOp`) 후 원정 시작(`kind: 'strategic'`, `opId`)
- 작전 지도의 마지막 노드는 보스 대신 고유 '작전 목표' 노드(주황 대형 마름모, 별 아이콘). 목표 노드 전투 승리 → `objectiveAchieved` 기록만, 영토는 아직 변화 없음
- 원정 종료 시 `settleOp`: 목표 달성 + 귀환(완료 또는 목표 달성 후 중단·귀환) = 성공 → 작전 보상·전진 거점(3) 또는 통제권(4) 1회 지급, 연결 지역 해금. 목표 전 철수·패배 = 아무것도 확보하지 않음(재시도 가능, 시도 횟수 기록)
- 전략 작전은 일반 원정 기록(출격/완수)에 포함되지 않음
- 원정 지도에 작전 목표 패널(미달성 / 목표 달성·귀환 필요), 전투 화면 '작전 목표 전투' 표시, 결과 화면에 목표 달성·귀환·작전 판정·작전 보상
- 세이브 검증: 전략 작전 원정은 작전 ID·지역 일치·작전 기록 존재 필요. 작전 도중 저장/불러오기 지원
- 부가 목표는 표시만 하고 판정 기준은 미정

## 지역 탈환 PHASE 5: 지역 개발 (`systems/regionDev.ts`, `ui/screens/RegionManageScreen.tsx`)
- 메인 메뉴 "지역 관리"(또는 전략 지도의 통제 지역 → "지역 관리 · 개발"). 통제권(상태 4 이상) 지역만 개발 가능
- 지역 유형별 시설 2곳(`data/regionDev.json`, 임시): 통제권 확보 시 모두 '손상' 상태 → 자원 투입 복구(게임 시간 소요, 일부 연구 필요) → 노동 인구 배치해야 생산 → 운영 중지/재개
- 정부 경제에 합산: 지역 생산·시설 소비, 지역 기본 유지비(예산·식량), 운영 시설당 유지비, 잔존 침식 관리비(침식 1당 예산). 지역 인력은 노동 인구 한도를 기지 시설과 공유
